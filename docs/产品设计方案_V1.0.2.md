# 协会会议执行 ERP 产品工作流程图和产品原型图设计方案

> 版本：V1.0.2 ｜ 日期：2026-10-17

## 1 产品定位

协会会议执行 ERP 以 `MeetingProject` 为会议项目根对象。Web 管理后台负责治理、配置、财务、核销、审计和归档；微信小程序负责立项填报、嘉宾触达、报名签到、现场执行和材料采集。系统另含消息中心（通知触达）与数据看板（决策分析）作为支撑模块。

## 2 正式流程

1. 立项申请：填写会议时间、主题、形式、预算和初版议程，支持用户自主填写与管理员转发填写；外部用户自主立项需管理员预审或验证码，防垃圾。
2. 筹备管理：维护合同、企业邀请招商、嘉宾、议程、资源和任务计划；合同 / 招商在此签订与归档，不产生付款动作。
3. 会务执行：处理报名签到（强制实名）、嘉宾邀请、会务任务、会务需求确认明细、现场执行与异常。
4. 材料中心：上传终版议程，按议程课题清单生成材料待办，人工上传后做题目 / 名称比对；维护课件、串场、劳务收集表、劳务协议、讲者照片和自定义模块。
5. 会后核销：核对权益、材料、劳务、合同、签到和现场成果，并处理例外（详见第 6 节）。
6. 财务结算：维护学会公付、个人报销、厂家付款凭证、发票归档和结算记录。报销是结算的一种类型（个人报销），非独立阶段 / 模块；所有付款（公付 / 报销 / 厂家款）统一在此触发，且必须以「已核销」为前置条件。
7. 档案归档：生成可检索、可导出、可审计的项目数字卷宗。

## 3 权限

- 总管理员：全平台范围，可修改全部后台业务数据；所有关键操作写入审计。
- 协会管理员：仅所属协会范围。
- 会务执行人员：仅获授权会议范围。
- 财务与核销角色：仅获授权项目范围，且结算必须以核销结论为前置条件。
- 普通用户与嘉宾：仅本人数据范围。

**权限矩阵（角色 × 模块 × 操作）**

| 角色 | 立项·筹备 | 会务执行 | 材料中心 | 会后核销 | 财务结算 | 档案中心 | 系统配置 |
|---|---|---|---|---|---|---|---|
| 总管理员 | 全部操作 | 全部 | 全部 | 全部 | 全部 | 全部 | 全部 |
| 协会管理员 | 查/编/审(本协会) | 查/编(本协会) | 查/编(本协会) | 查/审(本协会) | 查/审(本协会) | 查(本协会) | 字典/角色 |
| 会务执行人员 | 查(授权会议) | 查/编(授权会议) | 查/编(授权会议) | 查(授权会议) | 无 | 无 | 无 |
| 财务与核销 | 查(授权项目) | 查(授权项目) | 查(授权项目) | 查/审(授权项目) | 查/编/审(授权项目) | 查(授权项目) | 无 |
| 普通用户/嘉宾 | 自建立项查/编 | 本人报名/签到 | 本人上传 | 无 | 无 | 无 | 无 |

- 删除：仅总管理员 + 协会管理员；历史材料 / 已结算数据不可物理删除，仅软删 / 冻结。
- 所有关键操作（编辑 / 审批 / 删除 / 结算 / 核销结论）强制写审计。
- 敏感字段加密：银行收款信息、人脸 / 签到影像等敏感数据字段级加密存储，仅财务 / 核销角色可解密查看，最小化采集。

## 4 关键原型规范

### Web 后台

一级模块（10 项）：

| 模块 | 定位 |
|---|---|
| 工作台 | 首页聚合：我的待办 / 本周会议 / 异常预警（非业务模块） |
| 项目管理（会议） | 会议列表与详情 |
| 筹备管理 | 合同 / 招商 / 嘉宾 / 议程 / 资源 / 任务 |
| 会务需求确认明细 | 设计 / 制作 / 现场 / 其他 四组需求 |
| 会务执行 | 报名签到、嘉宾邀请、会务任务、现场执行与异常 |
| 材料中心 | 课件 / 串场 / 劳务表 / 协议 / 照片 / 自定义 |
| 会后核销 | 6 步 SOP + 例外单 |
| 财务结算 | 公付 / 报销 / 厂家款 / 发票 |
| 档案中心 | 数字卷宗检索 / 导出 |
| 审计日志 | 跨模块全量操作留痕 |

### 微信小程序

协会活动首页、立项申请、活动详情、嘉宾邀请、执行待办和材料采集为关键页面。普通用户活动详情显示立即报名、活动签到、分享活动；管理员显示嘉宾邀请、分享活动、材料收集。建议补充管理员审批入口（移动端闭环审批）。

### 会务需求确认明细

按设计、制作、现场执行和其他四组管理。每条需求至少记录是否需要、规格或数量、负责人、交付时间、预算归属、附件和执行状态。

### 材料中心

固定模块为课件、串场、劳务收集表、劳务协议；同时支持讲者照片和自定义模块。固定模块可按会议启用或停用，但历史材料不可被删除。材料识别机制：系统按议程课题清单生成材料待办，人工上传后做题目 / 名称字符串比对。

### 核销与财务

会后核销在财务结算之前。财务结算中保留学会公付、个人报销、厂家付款凭证和发票归档；报销是结算类型，不单列阶段。时序澄清：合同 / 招商仅在筹备签订，付款全部集中在财务结算（已核销后）触发；核销第 6 步「会务板块一致」仅核对合同↔结算单↔发票一致性，不付款。

### 系统配置

- 角色字典维护。
- 权限角色管理。
- 协会 / 会议基础配置。

### 消息中心 / 数据看板

- 消息中心：站内信 + 可选短信 / 邮件 / 企微；触发点：立项审批、报名、签到异常、核销不通过、例外单、付款完成。
- 数据看板：协会年度会议数、人均会议成本、合同履约率、嘉宾到会率、核销通过率；按协会 / 时间筛选。

## 5 验收要点

服务端必须校验角色与数据范围；状态不可绕过阶段门；材料、财务和归档均具备项目关联、附件、版本与审计记录；核销未通过时不允许生成可付款结算；敏感字段加密与最小化采集；例外单未闭环前不得结算。

**核销专项验收：**
1. 系统必须能拉取 / 上传线上时长与签到表，并按 30 分钟阈值自动判定参会合规性。
2. 劳务 5 字段（会议名 / 时间 / 角色 / 金额 / 银行收款信息）、会务 3 单（合同 / 结算单 / 发票）字段不一致时，系统必须阻断结算并高亮差异。
3. 药企 logo 出现在非首页 / 尾页 / 鸣谢页时，串场材料不得通过核销（医药会议合规红线）。
4. 任一核销步骤不通过必须可进入例外单，且例外未闭环前不得结算。
5. 核销每一步结论（含基线文件、比对结果、例外）写入审计，可回溯。

## 6 会后核销工作流 SOP

### 6.1 核销总原则

- 核销是财务结算的唯一前置门：核销未通过，禁止生成任何可付款结算。
- 核销对象 = 单个 `MeetingProject`（会议项目）。
- 每一步的核对动作 + 校验点 + 结论都必须落审计：角色 / 范围 / 时间 / 前后值 / 附件证据。
- 任一环节不通过 → 进入例外单流转，不得静默放过。

### 6.2 核销 6 步 SOP

| 步 | 名称 | 输入物 | 核对动作 | 校验点（通过条件） | 责任人 | 系统支撑点 |
|---|---|---|---|---|---|---|
| 1 | 提取已盖章通知 / 招商函 | 盖章版会议通知、招商函（PDF / 扫描件） | 从材料中心提取，作为核销基线 | 文件已盖章；为终版；会议名 / 时间 / 主办方 / 招商主体清晰 | 会务执行 / 核销 | 材料中心「已盖章公文」分类 + 版本锁 |
| 2 | 照片三处一致 | 现场照片 + 议程 + 劳务收集表 + 劳务协议 | 核对参会人员同时出现在 ①议程 ②劳务收集表 ③劳务协议 | 三处名单相互覆盖，无「在照片有人但三表无」或「表有但无到场证据」 | 核销 | 名单交叉比对（议程 ∩ 劳务表 ∩ 协议） |
| 3 | 参会数据（线上 / 线下 / 混合） | 签到表 / 线上平台时长数据 | 见 6.3 时长规则 | 见 6.3 | 核销 | 线上平台时长对接 + 30 分钟阈值自动判；线下签到表上传 |
| 4 | 参会材料：课件 + 串场 | 课件、串场 PPT | 见 6.4 材料规则 | 见 6.4 | 核销 | 题目字符串比对；药企 logo 位置检测（建议人工） |
| 5 | 劳务板块一致 | 劳务收集表、劳务协议 | 两端字段比对 | 会议名 / 时间 / 角色 / 劳务金额 / 银行收款信息 5 字段一致 | 核销 | 字段级自动比对，金额 / 银行号差异高亮 |
| 6 | 会务板块一致 | 会务合同、会务结算单、会务发票 | 三单字段比对 | 金额 / 会务名称 / 会议时间等一致 | 财务 + 核销 | 三单字段级比对 |

### 6.3 第 3 步 · 参会数据规则（时长）

| 参会形式 | 判定条件 | 通过要求 |
|---|---|---|
| 纯线下 | 有签到表 | 签到表存在且名单完整即可 |
| 纯线上 | 有角色的参会老师 | 在线时长 > 30 分钟（每位有角色老师都要满足） |
| 线上 + 线下（混合） | 同时满足 | 签到表 + 参会数据 双满足 |

**角色字典**：「有角色的参会老师」由系统配置的角色字典定义，前 4 类（讲者 / 主持 / 讨论嘉宾 / 点评专家）计线上时长且计劳务。

**线上时长对接**：对接腾讯会议开放 API、小鹅通 / 有赞直播、视频号直播等；统一字段 `user_id, meeting_id, join_time, leave_time, duration_sec, role`；平台不可达时允许人工导入 CSV / 平台导出，标注「人工补录」留审计，时长判定仍按 >30 分钟阈值。

### 6.4 第 4 步 · 参会材料规则

- 课件：课件课题是否在议程的中课题列表内；对不上 → 退回补件。
- 串场：主图题目是否跟立项会议名字一致；是否含主办方名 + logo。
- 合规红线：药企 logo 只能放首页、尾页、鸣谢页，不得出现在内容页 / 课件页（医药行业会议合规铁律，审计重点）。

### 6.5 第 5 / 6 步 · 一致性校验字段

- 劳务板块（收集表 ↔ 协议）：会议名字、会议时间、角色、劳务金额、银行收款信息（5 项）。
- 会务板块（合同 ↔ 结算单 ↔ 发票）：金额、会务名称、会议时间等。

一致性校验是核销里最适合系统硬校验的部分：两端同字段做字符串 / 数值比对，差异高亮 + 阻断结算。

### 6.6 例外与风险

以下情形一律进例外单（状态机：待处理 → 处理中 → 已解决（触发重新核销）/ 已驳回（维持不通过，升级通知））：

1. 照片有人但三表无：疑似冒领劳务 → 暂停劳务付款，核实身份。
2. 线上老师时长 < 30 分钟：是否网络中断 / 中途退出 → 需补证明或扣减。
3. 课件不在议程课题：退回补件，延期核销。
4. 药企 logo 位置违规：合规拦截，必须改版重传。
5. 劳务 / 会务字段不一致：金额差、银行号错、名字错 → 退回更正，更正后重新比对。
6. 基线文件未盖章 / 非终版：不允许以此基线核销。

**例外单字段与 SLA**：`exception_id, project_id, trigger_step, type, description, evidence, assignee, status, resolution, recheck_at`。默认指派会务执行 / 核销负责人，可转交；普通例外 2 个工作日内处理，合规类（药企 logo、冒领劳务）即时阻断付款；未闭环前对应项目锁定结算。

## 7 项目状态机与阶段门

项目主状态沿 7 阶段推进，阶段门不可跳：

```
草稿 → 待审批 → 已立项 → 筹备中 → 执行中 → 待核销 → 已核销 → 已结算 → 已归档
                                   ↑                  │
                                   └── 例外单未闭环 ──┘（已核销不可达，除非例外解决）
```

- 阶段门硬约束：待核销 → 已核销 必须 6 步全通过；已核销 → 已结算 必须有核销结论；已结算 → 已归档 必须有结算记录 + 材料完整。
- 回退：仅「已立项」后允许撤销 / 暂停（写审计 + 通知）。
- 各阶段内部可再细分完成度，不影响主状态推进。

## 8 角色字典

系统配置 → 字典表维护，供议程、劳务收集表、劳务协议、参会数据统一引用：

| role_code | role_name | 计线上时长 | 计劳务 | 说明 |
|---|---|---|---|---|
| speaker | 讲者 | 是 | 是 | 课件 / 课题主体 |
| host | 主持 | 是 | 是 | 环节主持 |
| panelist | 讨论嘉宾 | 是 | 是 | 讨论 / 圆桌 |
| reviewer | 点评专家 | 是 | 是 | 点评 / 审稿 |
| coordinator | 会务协调 | 否 | 否 | 工作人员，不计费 |
| audience | 普通听众 | 否 | 否 | 仅报名，不参与劳务 |
| staff | 签到 / 执行 | 否 | 否 | 现场执行人员 |

- 有角色的参会老师 = 前 4 类（计时长 + 计劳务）。
- 字典可扩展；新增角色需同步评估「是否计时长 / 劳务」两个开关。

## 9 数据与合规

- 敏感字段加密：银行收款信息、人脸 / 签到影像等敏感数据字段级加密存储，仅财务 / 核销角色可解密查看，最小化采集。
- 数据迁移：提供 Excel 导入模板（会议 / 嘉宾 / 合同 / 历史结算），含字段映射与校验报告，解决协会历史数据入库。
- 发票验真：对接航信 / 百望发票平台做发票查验，或上传 + 人工验真 + 状态标记。
