# 立项函与 Word 项目通知函（阿里云测试版）

## 业务流程

1. 项目创建人填写会议名称、日期、预算、负责人及初版议程，保存为草稿或提交立项。
2. 所属协会管理员或总管理员在「会议项目 → 项目详情 → 概览 → 立项函及项目通知函」查看、修改立项函标题和正文；允许在草稿/待审批阶段修改。
3. 所属协会管理员或总管理员上传本协会的 DOCX 固定通知函模板。模板会应用于该协会随后批准的会议项目。
4. 正式审批通过后，系统同步锁定立项函标题、正文、会议基本信息与所用 Word 模板的文件键/版本，将批准时间和审批人记入快照。
5. 有权查看该会议内部信息的业务人员可下载 项目通知函-待盖章.docx，在线下打印或带往有权限的盖章流程。下载不等于盖章或正式发文。

## Word 模板使用方法

模板可保留 Word 页眉、公文红头、字号、表格、署名与空白盖章区。占位符写在 Word 文本中，使用双大括号：

| 占位符 | 含义 |
|---|---|
| {{会议名称}} | 会议名称（必填） |
| {{立项函正文}} | 管理员核对后的立项函正文（必填） |
| {{通知函标题}} | 项目通知函标题 |
| {{立项函标题}} | 立项申请函标题 |
| {{项目编号}} | 项目编号 |
| {{协会名称}} | 项目所属协会 |
| {{会议日期}} | 会议开始日期 |
| {{会期}} | 如 2天 |
| {{会议形式}} | 线下、线上、混合 |
| {{预计参会人数}} | 人数 |
| {{预算金额}} | 元，保留两位小数 |
| {{项目负责人}} | 项目负责人 |
| {{承办部门}} | 承办部门 |
| {{初版议程}} | 初版议程要点 |
| {{审批人}} | 通过立项的审批人 |
| {{审批日期}} | 审批日期 |
| {{发文日期}} | 与审批快照相同的日期 |
| {{联系电话}} | 项目联系电话 |
| {{发文说明}} | 未盖章提示；历史补发时说明 |

没有上传自定义 DOCX 时，使用系统内置 Word 模板。上传时校验模板（必须包含两个必填占位符；其他字段仅允许表内列明名称）。

## 权限与历史管理

- 立项函修改、协会级模板上传和预览：该协会管理员、总管理员；不能跨协会。
- 正式 Word 下载：限项目有权访问的内部角色；参与者/嘉宾不能下载。
- 审批通过后，立项函锁定，不允许通过普通资料修改接口重写批准快照；后续变更应走项目变更流程。
- 替换 Word 模板不会改变已通过审批的项目通知函。快照绑定源模板文件键和版本；旧源文件须纳入备份。
- 历史已审批项目若没有通知函快照，管理员可选择「历史项目补发通知函」，系统明确添加「依据当前资料补发、非原审批日快照」说明并记录审计。

## 部署与验收

- Node.js 22.5+，依赖 docxtemplater 和 pizzip，运行 npm install --omit=dev。
- ERP_UPLOAD_DIR 对应的文件目录需持久化并纳入备份；模板按已上传附件存储。
- 新增三张数据表：project_initiation_letters、project_notice_templates、project_notices。
- 回归测试：node --experimental-sqlite --test test/project-notice.test.js；全量 npm test；Cloudflare 兼容 npm run test:cf。
- 阿里云测试版部署前应备份数据库和上传目录，并确认测试环境版本。GitHub 合并不代表服务器已经部署。

## 盖章边界

本模块只生成待盖章 Word，不模拟真实签章，也不提供审批后静默改正文的通道。线下盖章扫描件仍应走已有材料上传/归档流程。
