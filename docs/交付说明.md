## 可点击演示版（09_可点击演示版/index.html）

交付方案之外补了一套**能真点的工作台**，用来验证流程本身是否讲得通，而不是只看静态原型图。

- **形态**：单个 HTML 文件（约 188 KB），CSS 与 JS 全内联，零外部依赖。双击用浏览器打开即可，可直接微信/邮件发出去。
- **数据**：全部为**演示假数据**（写死在文件内常量，刷新即复位，不落库、不写 localStorage），顶部常驻「演示数据 · 非真实业务」标签。28 个项目的会议名/协会/预算/日期/负责人/核销进度互相自洽。
- **覆盖范围**：Web 后台 11 个一级模块、**58 个末级页面（最深 4 级菜单）** 全部可进；5 个角色切换后侧栏菜单、数据范围、KPI、待办清单同步变化（总管理员 58 页 / 协会管理员 50 页 / 财务与核销 44 页 / 会务执行 40 页 / 普通用户 19 页）。
- **项目上下文**：筹备 / 会务需求 / 会务执行 / 材料中心 / 会后核销 / 财务结算 六个页面均带项目下拉，切换后标题、金额、汇总条一起变；合同与招商金额按项目预算等比缩放，不会出现「合同总额 > 会议预算」。
- **可点出来的关键闭环**：
  1. 会后核销 6 步逐步判定「通过 / 不通过」，判不通过**自动生成例外单**；
  2. 6 步未全通过或例外单未闭环时，财务结算页**整页蒙灰锁定**，并明确写出缺哪几步；
  3. 例外单「标记已解决」→ 对应步骤自动转通过 → 6 步凑齐 → 「提交核销结论」解锁 → 状态 待核销→已核销；
  4. 结算解锁 → 「生成结算单」→ 已结算（金额与结算单明细一致）；
  5. 已结算 → 档案中心「生成卷宗」→ 已归档（项目冻结）；
  6. 以上每一步操作**实时追加审计日志**（4W1H：角色 / 范围 / 时间 / 前后值 / 附件）。
- **硬约束是真的拦得住**（不是文案）：核销未通过时提交按钮灰、财务整页锁；已结算项目核销步骤转只读且不再出现「生成结算单」（防重复付款）；未结算项目不能归档；角色数据范围外看不到项目与模块。
- **定位**：这是流程验证件，不是生产系统。流程上如有分歧，现在改成本最低；确认后再把假数据层换成真库（云数据库 + 登录鉴权），页面基本不用重画。

### 第六轮：全角色全功能点检、导出落地与全流程总览

第五轮把「页面」补齐了，但**按钮是不是每个都能用、每张表的每个字段是不是都真的校验**没有系统验过。这一轮把点检粒度从「页面」下沉到「按钮和字段」，并把几处「演示版未接入」的占位实现掉。

**① 点检口径：不抽查，全量**

- 渲染巡检：5 角色 × 58 末级页 = **211 个组合**，逐页检查横向溢出 / 空页 / 标题折行 / 文本里的 `undefined`、`NaN`、`[object Object]`。
- 按钮点检：把每页的**每一个 `data-act` 按钮逐个点一遍**（全站约 700 次点击），用「路由 + 内容哈希 + 弹窗 + 抽屉 + 提示」五项判定是否真有响应；禁用的按钮单独标记，不算死按钮。
- 表单点检：16 张表单逐张走「空提交 → 逐字段填 → 再提交」，比对**标红数是否等于必填数**、填完红框是否清零、提交后数据增量、审计是否写入、弹窗是否关闭。
- 以上在 1440 与 1024 两个宽度各跑一遍。

**② 查出并修掉的 6 个问题**

1. **必填下拉形同虚设**（最严重）。`<select>` 天然默认选中第一项，`validateForm()` 读到的值永远非空，于是「所属协会 / 会议形式 / 角色 / 数据范围 / 付款类型 / 关联项目」这些必填下拉**留空也能提交**。立项表单 8 个必填只标红 6 个，合同 5 个只标红 0 个。→ 必填下拉首项改为 `请选择…`（`value=""`），改完 16 张表单的标红数全部等于必填数（立项 8/8、合同 5/5、付款 4/4…）。
2. **弹窗「重置」无效**。`formReset` 只调 `render()`，重绘的是弹窗背后的页面，弹窗里的值纹丝不动；而且弹窗里原本根本没有重置按钮。→ 弹窗重置改为「重开一张干净表单」，并给弹窗底栏补上「重置 / 取消 / 提交」三键。
3. **「+ 新建立项」是死按钮**。只弹一句「演示版未接入」，但立项表单其实早就做好了。→ 改为直接跳转「项目管理 › 立项管理 › 立项申请」。
4. **「导出」是假的**。只弹「导出未接入」。→ 改为前端生成**带 BOM 的 CSV 真下载**（Excel 双击不乱码），文件名形如 `全部项目-10-18_1218.csv`，同时写一条「导出记录」和一条审计日志；入口补到项目列表、审计日志、档案检索三处。
5. **「导出卷宗」是假的**。→ 改为生成含**核销 6 步结论 / 结算金额 / 例外单 / 审计留痕**四段的文本卷宗并下载（实测 357 字节，四段齐全）。
6. **文件上传位是个死图标**。`.upload` 只是个 `div`，点了没反应。→ 改为 `<label>` 包真实 `input[type=file]`，点开是系统选文件对话框，选中后回显文件名（演示版不落盘）。

**③ 新增「全流程总览」页**

「工作台 › 数据看板 › 全流程总览」，专门解决"工作流讲不清"：7 段流程条（每段显示当前停几个项目，点一下直接跳到该阶段工作页）+ 在库 / 卡核销 / 已归档三个 KPI + **阶段职责与闸门**表（谁负责、做什么、卡什么）+ 核销 6 步 SOP + 三条硬约束 + 9 状态 8 流转的状态机。汇报时照着屏幕念即可，不用背。

### 第七轮：权限模型校正 —— 总管理员 = 超级角色

原实现里总管理员虽然拥有全部 11 个模块，但有两处没有真正「全覆盖」，属于权限模型上的漏项：

1. **待办中心按角色过滤**：`TODOS.filter(t => t.roles.includes(state.role))` 让总管理员只看到标了 `admin` 的 4 条，漏掉「结算待触发」（只标 finance）和「嘉宾待签到」（只标 user）—— 而这恰恰是总管理员该统筹的活。
2. **权限矩阵缺「数据范围」维度**：矩阵只表达模块级的全权 / 只读，没体现「全平台 vs 本协会 vs 授权会议 vs 授权项目 vs 本人」，也看不出总管理员到底覆盖了多少项目。

校正内容：

- `ROLES.admin` 增加 `super:true`，新增 `isSuper()`；`visibleProjects(role)` 支持传入角色，便于跨角色统计。
- **待办中心**：总管理员看到全部 6 条（含财务专属、嘉宾专属），并新增「归属角色」列（短名徽标 + title 全称），一眼看出这条活本来该谁干。
- **权限矩阵 · 按角色查看**：总管理员行加「超级」徽标；顶部加绿色说明条「11 个模块全权 + 全平台数据 + 可代行其余四角色全部操作，无需切换身份，其余角色权限都是它的子集」；新增**「数据范围与规模」**表（角色 / 数据范围 / 可见项目 / 可写模块 / 结论），实测总管理员 28/28、11 全权 0 只读 0 不可见，其余角色 4/10/12/1。
- **权限矩阵 · 按模块查看**：总管理员列表头加 ★，脚注说明该列即全集。
- **角色列表**：总管理员行加「全部权限」徽标，模块数显示 `11 / 11`；说明文案改为「超级角色：11 个模块全权、全部项目可见，可代行审批 / 核销 / 结算 / 归档 / 资料修改」。
- **「查看权限」弹窗**：总管理员弹窗顶部加超级角色说明条，11 个模块全部「全权」。
- **成员与授权**：角色下拉新增「总管理员（全平台）」，可授予该身份。
- **顶栏**：仅当身份为总管理员时显示绿色标签「全部权限 · 全平台」，其余角色不显示。

校正后总管理员**无需切换身份**即可完成：立项审批（协会管理员职责）、核销 6 步判定与例外处理（财务与核销职责）、生成结算单与付款（财务职责）、生成卷宗归档（协会管理员职责）、合同 / 招商 / 嘉宾 / 议程 / 任务等资料录入（会务执行职责）。

复测：211 组合 × 1440 / 1024 两宽度 **0 问题 / 0 死按钮 / 0 表单问题 / 0 报错**；待办 6 行 6 列单行不折行；权限矩阵两表 5 行 + 5 行。
