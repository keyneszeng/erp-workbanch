## 2026-11-01 会规化会务执行系统：十项业务整改

本次是单代码仓库三种模式共用的功能改造；`ERP_DEMO_MODE=1` 继续为 Cloudflare 演示，测试版使用隔离数据库，阿里云 ECS 生产独立持久化数据。**PR 合并不自动修改现网数据库或上线**。

1. UI 对外名称统一为「会规化会务执行系统」；不修改已部署域名或内部目录、环境变量名。
2. 总管理员在用户与权限内增加/停用协会目录，持久化 `associations`，有关联账号/项目不允许删除，须先迁移数据；历史协会默认首次导入。
3. 单用户部署：仅总管理员一个有效账号时，选本协会成员显示并允许指定该账号为负责人；有常规协会成员时按本协会范围选人。
4. 审批中心待审批表允许总管理员调整单笔审批时限，全部写审计；已审批单不可修改。
5. 企业/嘉宾专属邀请函生成后可以同源在线 PDF 预览（不对外公开，也不等于已发出）；历史记录有预览与下载操作。
6. 附件上传保留 8 MB 上限，支持旧版 PPT / PPTX / XLSX / DOCX / PDF 及图片。旧 PPT 只作为附件下载，不执行文件内容；上传格式仍以服务端真实文件识别为准，legacy CFB 无法像 OOXML 一样强验证内部文档类型，管理员应限制可上传角色。
7. SOP 第一关为盖章通知/招商函的合法性及会议字段，不检查课件；第四关才核验课件与终版议程课题、串场和 Logo，避免重复。
8. 正式核销第六步：拟请款总额必须等于已签署合同总额；应开票合同金额与发票金额相等。已核验劳务专家合同按第五步免票单独列支。核销之前不得申请付款；全部付款与合同总额一致才能结算。
9. 第五步展示「劳务专家」合同类别与「专家费 / 个人报销」付款类型，区分材料来源，不把劳务合同放到发票台账。
10. 新付款申请删除发票号输入，优先选择已签合同 vendor 或第五步劳务核验的收款人。敏感劳务账号只在服务器端使用 AES-256-GCM 加密，选择列表只提供尾号；启用严格核对可设置 `ERP_REQUIRE_VERIFIED_PAYEES=1`（需补齐老项目的已核验收款人）。

### 财务加密必需配置（生产）

在阿里云 ECS 的安全环境配置 `ERP_FINANCIAL_DATA_KEY`（64 位十六进制、32 字节随机值）。**不要写入 Git 仓库**，不要和数据库一起备份到公开位置。缺少密钥时，系统不会持久化第五步劳务银行账号，仍可人工核验；上线前需补录历史劳务收款记录后才能开启 `ERP_REQUIRE_VERIFIED_PAYEES=1`。轮换密钥前必须先迁移加密数据，否则旧记录无法解密。所有操作受项目范围和财务动作权限限制。

> 注意：不要删除有记录的协会；不要因为旧 PPT 允许归档而将其视为安全、可在线预览或可信的财务凭证。
