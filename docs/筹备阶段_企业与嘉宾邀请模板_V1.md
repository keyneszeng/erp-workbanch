# 会议项目筹备阶段：企业邀请（招商）与嘉宾邀请

更新时间：2026-10-29

## 业务定位

两个邀请功能都归属于**会议项目详情 → 筹备管理**。立项通过后自动启用**内置固定文档模板**，不要求负责人重复填写会议名称、时间、主办协会、形式、议程和项目负责人。

- 企业邀请（招商）：受邀对象以企业/机构为主，可填写单位、称谓/负责人名头、邮箱。
- 嘉宾邀请：受邀对象以讲者/专家为主，可填写姓名、职称/称谓、嘉宾角色、拟交流课题、邮箱。
- 模板目前使用内置固定版式 V1（后续可扩充协会专属 Logo/抬头模板、印章、编号与多语言）；系统生成时保存**不可静默修改的内容快照**。
- 邮件或微信小程序只负责发送/打开邀请函，不改变立项、核销、财务状态。

## 核心流程

1. **立项审核通过**：项目状态从“待审批”变成“已立项”；筹备阶段可访问内置两份模板。
2. **自动匹配**：实时从项目抽取会议名称、主办协会、会议日期、会议形式、初版议程、项目负责人；没有字段时使用明确的待确认说明，禁止编造地点、嘉宾头衔和合作权益。
3. **个性化**：负责人填写受邀单位或嘉宾姓名、职务/称谓、角色/课题和邮箱。
4. **生成 PDF**：创建模板版本、会议字段与受邀人字段快照；允许预览/下载。
5. **确认发送**：
   - 邮件：用户确认收件邮箱；服务端 PDF 附件通过已配置邮件服务发出；只有提供商确认受理后更新“已邮件发送”。
   - 微信：生成高熵分享令牌和小程序分享路径；在小程序中由负责人执行分享。生成路径不代表已实际送达。
   - 这版为避免令牌轮换让旧邮件/卡片失效，**同一邀请函在选择已发送渠道后不可切换渠道**；若需另一渠道，重新创建该邀请函。
6. **受邀回复**：嘉宾/企业可点击受邀页面中的“确认接受/暂不接受”；同一令牌重复相同操作幂等，不允许互相覆盖。
7. **回写会议项目**：所有邀请状态归属于会议项目；嘉宾的确认/拒绝结果同步到项目嘉宾档案，并以 invitation_id 关联，避免同名覆盖。
8. **审计**：记录创建人、发送人、时间、渠道、模板版本、受邀对象、回复与撤销；敏感邮箱不写入公开操作记录。

## 技术接口

| 方式 | 路径 | 权限/语义 |
|---|---|---|
| GET | /api/projects/:id/prep/templates | 项目筹备模板 + 会议字段预填 |
| GET | /api/projects/:id/prep/invitations | 会议级邀请函列表 |
| POST | /api/projects/:id/prep/invitations | 创建固定模板快照 |
| GET | /api/projects/:id/prep/invitations/:inviteId/pdf | 授权人员下载专属 PDF |
| POST | /api/projects/:id/prep/invitations/:inviteId/email | 显式通过邮件服务发送 PDF |
| POST | /api/projects/:id/prep/invitations/:inviteId/wechat-share | 签发小程序分享路径，状态仍是待分享 |
| POST | /api/projects/:id/prep/invitations/:inviteId/revoke | 撤销未完成邀请 |
| GET | /api/public/prep-invitation?token=... | 持有效邀请令牌可查看本人邀请 |
| GET | /api/public/prep-invitation-pdf?token=... | 受邀人下载 PDF |
| POST | /api/public/prep-invitation/respond | 令牌确认/拒绝，回写项目 |

## 上线接入前置条件

- 邮件：需在环境中设置服务端 Secret **ERP_RESEND_API_KEY**、验证后的发件邮箱 **ERP_MAIL_FROM**、公网 HTTPS 域名 **ERP_PUBLIC_BASE_URL**（例：https://erp.aibuild.work）。不能把密钥下发到浏览器/小程序。
- 微信：将 miniprogram/ 导入微信开发者工具、替换正式 AppID、配置 request/downloadFile 合法域名、发布审核。当前仓库此前没有原生小程序项目，新增的是邀请函最小工程，不是全量活动小程序。
- 同一个邀请函不支持“邮件发出后继续换微信分享”，需要再创建一份独立邀请实例（避免旧令牌失效）。
- 微信分享回调不能作为“已送达”的证据；只有受邀人回复才是确认事实。
- 邮件“已邮件发送”代表服务商受理；实际投递/退信需要接入邮件服务回调后才能提供准确的送达状态。
- 邀请链接含个人受邀信息，应避免被转发给无关对象；建议后续增加更精细的身份核对、退订、模板授权与邀请有效期策略。
