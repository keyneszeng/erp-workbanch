# ERP Web / 微信移动端原型对齐与业务边界（2026-11-01）

基线：用户提供的“Web 管理后台（主系统）B1–B5 / 微信小程序 C1–C6 / 角色职责 D”截图。所有示意数据为原型，不得当作真实业务统计；本次 UI 只显示后端可用的真实字段。

## 关键业务契约

- **Web 与小程序共享数据库、状态机和审批单。** 小程序普通用户在本人协会发起立项，产生草稿；提交后生成正常“立项审批”记录。不能绕过协会管理员审批直接入筹备。
- 普通用户只可编辑本人创建且状态为“草稿”的申请；跨协会申请、编辑他人草稿、重复提交均被服务端拒绝。正式小程序关闭时新增入口不可用。
- 数据范围由服务端按所属协会、负责项目、成员关系及创建人判断。普通用户会议详情脱敏，不含合同、结算、银行账号。
- **材料原件**受项目权限约束；结算后材料冻结。小程序采集仅支持图片；PDF/Office 由 Web 上传。OCR 提取建议仍必须人工确认。
- **财务硬门禁**保持六步核销 → 付款审批/财务执行 → 金额核对 → 正式结算 → 归档，UI 跳转不能放宽该顺序。
- **原型中的“报名、签到、嘉宾邀请管理、现场执行报告”没有对应安全后端时不渲染虚假操作按钮。** 真正上线这些能力需明确身份、签到方式、设备/位置与核验、去重、隐私及审计要求，不允许把点按钮视为真实签到。

## 验证范围

- Node API 测试包含普通用户申请/所属协会/本人编辑/其他用户越权/提交审批单/审批角色、以及原有全套核销财务回归。
- Chrome 黑盒脚本检查 Web 六指标、项目进度快捷入口、材料工作台、财务分区与浏览器错误。
- QA 另做模块 JS 语法、Cloudflare 演示版兼容 dry-run。
- CI 通过并不等于**微信真机验收**或阿里云 ECS 线上发布；当前仅改仓库主线，独立生产部署仍需审批与备份。
