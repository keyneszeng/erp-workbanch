01一页看懂

这是一套「会议立项 → 筹备 → 执行 → 核销 → 付款 → 结算 → 归档」的全流程管理系统。 核心不是表单收集，而是四个不可绕过的门禁：立项要审批、付款要核销、结算要无在途付款、归档要材料齐。 系统做的所有事，都是为了让这四道门「绕不过去、留得下痕、查得到人」。

三条设计主线

  • 状态机是唯一的真相。 项目能不能做什么，只看 projects.status。 所有「能不能点」都由状态 + 权限 + 门禁三者算出来，页面不自己编规则。
  • 门禁在服务端，不在按钮上。 前端隐藏按钮只是体验；真正拦住越权的是 assertCan() + scopeFilter() + GUARDS。直接敲 URL、直接打接口一样拦。
  • 每个写动作都留痕。 状态流转、审批、付款、核销判定、归档、导出、登录，全部写 audit_logs（Who / When / What / Which），审计日志不可改不可删。

02代码结构

分六层，从上到下依赖单向：浏览器 → 应用壳 → 页面 → 接口 → 内核 → 存储。 没有框架，没有构建步骤，node server/index.js 就能跑；同一份请求处理代码 既跑在 Node 也跑在 Cloudflare Worker 上（lib/app.js 的 handle() 两边共用）。

04主流程：9 状态 8 流转

项目的整个生命周期就是一条单向链，只有一处可以后退（待审批 → 草稿，驳回）。 每一步都绑定一个动作、一个权限、一组门禁；三者齐了才能走。

05核销 6 步与例外单闭环

核销是整套系统的重心：它是付款的唯一前置门。6 步必须按顺序判定，跳步的按钮是禁用的， 后端也会拒绝。任一步判「不通过」不阻塞流程，但会自动生成例外单，把决定权交给财务。

为什么「不通过」不直接把项目打回上一阶段：核销是对已发生事实的核对，事实改不了。 把项目退回「执行中」等于允许重做一遍，反而给「先付款后补核销」开了口子。 正确做法是承认这步不合规、由财务书面批准例外（并留痕），流程继续往前走。

06四道门禁链

从「待核销」到「已归档」，四道闸串成一条链，每道闸都有明确的判断条件和错误码。 这些判断全部在服务端，前端只是提前把按钮置灰并给出原因。

10关键不变量

下面这些是「无论谁怎么点都不会被破坏」的约束。改代码时如果动了其中任何一条， 必须先想清楚为什么 —— 每一条背后都有一次真实踩坑。

  1. 付款唯一前置门。只有「已核销」可新增付款（PAYABLE_STATUS）。已结算 / 已归档一律拒绝。
  2. 超预算按「分」比较。cents() 收敛后再比，否则 2789.69 + 2600.09 会算出 5389.780000000001，正好用尽却报超支。
  3. 核销 6 步顺序不可跳。前端把「判定」按钮置灰（prevUnjudged），后端再校验一次。
  4. 核销结论一冻结就不可改。有结算单 = 账目封账；已归档 = 卷宗封存。 assertNotFrozen() 统一拒绝删材料、改需求单、调成员。
  5. 结算必须无在途付款。否则结算单里的「支出」会漏掉还在审批中的钱，结余是假的。
  6. 归档必须材料 8/8。缺哪类直接点名，不让人猜。
  7. 数据范围永远作用在 projects p 上。子查询里换成别的别名， SQLite 会把它当外层引用，条件恒真 —— 曾经因此让协会管理员看到全平台已付款。
  8. 金额一律定点到分。入库、汇总、导出、结算单，四个地方用同一套 yuan()。
  9. 单号在事务内取。nextId() 保证并发下不重号（AP / EX / ST / PY 四个序列）。
  10. 每个写动作都写审计。包括导出、登录、改密 —— 审计日志只增不改不删。
  11. 页面可达性前后端同口径。lib/nav.js 的 canVisit 与 rbac.js 的 canVisitNav 必须同步改，否则工作台会给出点不动的按钮。
  12. 零第三方依赖。node_modules 可以是空的，交付环境常常没有网络。

11本轮巡检与修复（V1.2.11）

把 5 个角色 × 15 个页面共 75 个格子全走一遍，再把每格能点的按钮全枚举出来（235 个）。 24 个格子报问题，逐个核实后：21 个是模块白名单、3 个是数据范围，都是设计行为； 真正要修的是四类「看得见、点不动」。

#缺陷症状（哪个角色、哪个页面）改法
1 预警指向
无权限模块		 会务执行的工作台出现「去处理 → 财务结算」「去处理 → 审批中心」， 点了被路由守卫弹回工作台 —— 看着能点，点了原地不动 后端 alerts() 先问两件事：这个动作归不归你（payment:approve / verify:exception_approve / verify:check）、目标页面进不进得去 （新增 canVisitNav）；两个都过才生成预警。前端再兜一层 reachable()， 进不去就退到项目详情
