## 1. 唯一产品定位

**协会会议执行 ERP，以 Web 为主系统、微信小程序为移动协同端，以会议项目为核心。**

Web 管理后台负责项目治理、人员授权、会务需求、合同、企业邀请（招商）、核销、财务、数字卷宗及操作留痕；微信小程序负责用户填立项、报名/签到、嘉宾确认、会务现场任务、材料与讲者照片采集。

“阶段”与“系统状态”必须分开：产品层对外展示 7 个业务阶段，现有 9 个数据库状态可沿用以避免破坏历史数据。

~~~mermaid
flowchart LR
    A["1 立项申请"] --> B["2 筹备管理"]
    B --> C["3 会务执行"]
    C --> D["4 材料收集"]
    D --> E["5 会后核销"]
    E -->|核销通过| F["6 财务结算"]
    F --> G["7 归档总结"]
    E -->|有异常| H["补件/例外单/复核"]
    H --> E
~~~

> 既有项目状态“草稿→待审批→已立项→筹备中→执行中→待核销→已核销→已结算→已归档”仍是后端状态机，不等同于前端必须显示的阶段标题。用户要求删除“提交审核”等流程图文案，并非废除审批与审计。

### 1.1 立项申请
- 微信小程序首页有“立项申请”，字段为会议时间、主题、形式（线上/线下/混合）、预算、初版议程。
- 普通用户自行填写；总管理员/协会管理员可转发特定协会的填写入口。
- 支持草稿、提交、审核通过/退回、按申请转换会议项目；前端流程主文案不显示“提交审核”，后台审批继续保留。

### 1.2 筹备管理
- 合同与企业邀请（招商）；**不要用“招商企业”**，不要在此阶段列“发票”动作。
- 嘉宾/专家邀请：由总管理员、协会管理员、授权会务执行人员发送；普通用户不能发送。
- 会议议程与资源筹备；会议级人员分配。

### 1.3 会务执行
- 管理会务需求确认明细、设计制作、现场人员、嘉宾邀约、现场签到、议程执行、拍照和记录。
- **会务需求确认明细**为单会议、可勾选、可填写数量/规格/是否需要、负责人、预算、交期、附件的业务表单。四组如下：

| 分组 | 标准条目 | 必要可填写问题 |
|---|---|---|
| 设计 | 串场；议程A4单张；台卡；议程易拉宝；人头易拉宝 | 设计备注、规格、交期 |
| 制作 | 串场纸质版单面彩印；议程A4单张；台卡；易拉宝；产品易拉宝；横幅；讲台花；讲台包边；背景板 | 份数；装订；讲者台卡是否两份；人头/议程；各项是否需要 |
| 现场执行 | 控台；控场（含普通拍照）；专业摄影；线上端口 | 控台/控场/摄影所需人数；线上端口是否需要 |
| 其他 | 垫付；参会胸卡设计及实物；代购酒水；车队服务；其他 | 数量、金额、补充说明 |

- 需求单“已确认/归档”后的变更必须记录原因、操作人、前后值；不能无痕覆盖原始确认记录。

### 1.4 材料中心
- 首先**上传终版议程**（独立的版本文件，不覆盖初版），系统解析议程中的讲者、课题、环节，生成待收材料建议；**必须人工确认识别结果，才正式分配给会务执行人员**。自动识别是待开发能力，不能伪称已存在。
- 会议级可勾选固定模块：①课件（名称 + 照片/文档/PPT）；②串场（同）；③劳务收集表（名称 + 照片/文档/XLSX）；④劳务协议（名称 + 照片/文档/PPT）。
- 新增**讲者照片**模块：讲者姓名与上传照片，按议程讲者逐人跟踪“待上传/已上传/已确认”。
- 支持不限数量的**自定义模块**（名称 + 图片/文档/PPT），模块启停不删除已有材料；按照会议、模块、讲者/课题、上传人、版本组织归档。
- 当前仓库的“归档必备 8 类”应视为**归档完整度清单**，不能替代上述**采集模块**。两套概念通过映射配置衔接，不可简单合并成同一枚举。

### 1.5 会后核销（必须排在财务结算之前）
基于业务原始文件，核销规则目标为：
1. 提取已盖章会议通知/招商函，核对终版及名称、时间和主办方。
2. 核对现场照片人员与议程、劳务收集表、劳务协议的一致性。
3. 核对参会数据：线上有角色人员 **>30 分钟**；纯线下需签到表；混合会议同时需签到表与线上数据。
4. 核对课件课题与议程、串场主视觉名称/主办方标识，按业务要求审查企业 Logo 出现位置。
5. 核对劳务收集表与协议：会议名、时间、角色、劳务金额、银行信息。
6. 核对会务合同、结算单、发票信息一致性。

任一步不通过→例外/补件→复核；核销未通过，不开放付款结算。规则必须分清“系统可自动对照”和“需要人工判定”，不能把文字提示当作自动核验。

### 1.6 财务结算
- 独立类目：**学会公付、个人报销、厂家付款凭证、发票归档、结算记录**。
- 财务阶段总览不单列“报销”作为一个阶段；“个人报销”作为结算模块的业务类别仍保留。
- 排序明确为“厂家付款凭证 → 发票归档”；付款类操作须遵守核销及预算门禁。
- 上传付款凭证、合同、发票与结算单要能关联到同一会议、供应商、付款单和审计日志。厂家付款凭证是证据，不等同于当前 PAYMENT_TYPES 中的“厂家款”付款类型。

### 1.7 归档总结
- 审核与财务完成后生成数字卷宗；支持分类检索、下载、PDF/ZIP 清单、文件指纹与审计记录。
- 归档项目的“资料下载”保留为总管理员及授权协会管理员的可见与可执行操作。
- 已归档更正走“总管理员申请/执行解封 → 修改并留痕 → 重核销 → 重结算/重新归档”的有记录流程；不能直接覆盖已封存财务证据而不给版本号。

## 最新确认：立项后自动匹配筹备邀请函模板（2026-10-29）

**“企业邀请（招商）”与“嘉宾邀请”属于同一会议项目的筹备阶段，不再作为与会议项目脱离的独立活动业务。**

1. 立项审核通过后，会议项目自动开放两种内置固定模板；直接提取会议编号、名称、所属协会、日期、形式、议程要点、项目负责人，不要求筹备负责人重新录入。
2. 筹备负责人按模板类型输入受邀企业/机构名称或专家姓名，补充职务/称谓、角色、课题和收件邮箱，生成个性化 PDF；形成不可静默改写的模板版本与内容快照。
3. PDF 可供负责人预览/下载；发送必须由有权限人员显式确认。邮件发送和微信小程序分享为两个独立通道，不能把“生成分享链接”当作“微信实际已发送”。
4. 受邀方确认或拒绝后，邀请状态回写会议项目；嘉宾应同步归档到本项目的嘉宾名单，使用邀请 ID 关联，避免按姓名匹配时误覆盖同名讲者。
5. 邀请权限：总管理员、所属协会管理员、该会议有权限的会务执行人员；普通用户不能批量或单独发送业务邀请。
6. 生产接入需协会正式邀请函抬头/LOGO/公章用法审定、邮件服务域名与密钥、正式微信小程序 AppID 和分享配置、个人信息保护策略。

**研发进度**：新增代码草稿见 PR #6（固定模板、PDF、邀请状态/审计、邮件适配、Web 与小程序受邀页面）；在测试、密钥配置与微信发布完成前，不能宣称 erp.aibuild.work 的此项功能已经上线。

## 2. 角色与页面分工

| 角色 | 数据范围 | Web 关键能力 | 小程序关键能力 |
|---|---|---|---|
| 总管理员 | 全平台 | 全业务编辑、授权、审批、解封流程、导出和审计 | 如有需要可进入执行端 |
| 协会管理员 | 指定协会 | 会议、审批、邀请、执行、材料、合同、范围内报表 | 嘉宾邀请、分享、材料收集 |
| 会务执行人员 | 指定会议 | 需求确认、执行待办、现场取证、材料 | 嘉宾邀请、分享、材料收集、签到管理 |
| 财务人员 | 授权协会/会议 | 公付、报销、凭证、发票、结算 | 可只读本人授权待办 |
| 核销人员 | 授权会议 | 核销判定、异常、复核 | 可查看核销待办 |
| 普通用户 | 本人 | 无内部 ERP 后台 | 立项申请、立即报名、活动签到、分享活动 |
| 嘉宾/专家 | 本人邀请 | 无内部 ERP 后台 | 受邀信息、确认/拒绝、个人议程 |

权限每次在后端同时校验 **操作权限 + 协会范围 + 会议范围**。总管理员拥有最高业务修改权，但**审计记录不可自行抹除**。银行收款信息、身份证件、专家照片与参会记录应受最小权限保护。

## 4. Web 与小程序页面信息架构

**Web（主系统）**
- 工作台：今日待办、项目状态、缺件预警。
- 会议项目：列表、详情、时间线、人员与授权、业务完成度。
- 立项与筹备：申请详情、审批记录、企业邀请（招商）、合同、嘉宾邀请、议程安排。
- 会务执行：会务需求确认明细、任务责任人、签到/现场证据。
- 材料中心：终版议程、识别清单、固定/自定义模块配置、讲者照片、上传记录与版本。
- 会后核销：六步证据核对、差异高亮、例外处理、复核。
- 财务结算：学会公付、个人报销、厂家付款凭证、发票归档、结算记录。
- 档案中心：数字卷宗、PDF/ZIP 导出、审计。
- 系统管理：协会、角色、授权、安全与日志。

**微信小程序（移动协同）**
- 普通用户：协会首页→立项申请/我的申请→会议详情→报名/签到/分享。
- 会务执行：我的会议→会务需求/执行待办→嘉宾邀请→材料模块勾选→拍照/文档上传→进度。
- 嘉宾：受邀卡片→确认/拒绝→角色与课题→本人会议信息。

交互原则：普通用户的活动详情只显示“立即报名 / 活动签到 / 分享活动”；管理员或授权会务执行人员显示“嘉宾邀请 / 分享活动 / 材料收集”，每一按钮还必须经过服务端权限校验。
