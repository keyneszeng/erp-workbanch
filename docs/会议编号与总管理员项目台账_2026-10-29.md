# 会议编号与项目台账实施说明（2026-10-29）

## 唯一会议编号

会议项目以 projects.id 为唯一、不可修改的主键，编号示例 MP-2026-019。创建立项草稿时预留编号，审批通过后该编号正式启用。历史编号不得改变、重排或复用。

所有业务模块使用同一个会议编号作为关联键：contracts.pid、payments.pid、settlements.pid、materials.pid、verify_steps.pid、demand_sheets.pid、prep_invitations.pid 等。附件仍使用不可猜测的随机文件 Key，通过材料/合同等原始单据关联 pid，不改变已发布的对象存储路径。这样无需迁移原始业务表，避免资料关联断链。

## 付款与结算 → 项目台账

仅总管理员可访问，按会议编号实时汇总原始业务表，不生成第二套可编辑的财务记录。提供台账列表、按编号/会议名称/协会检索、单项目明细以及 CSV 导出。

每个项目包括预算、合同总额、签署合同总额、有效付款申请、已付款、待审批与待付款、结算收入、结算支出、结余、差额和资料覆盖情况。明细展示合同原件、付款单、发票号、财务归档附件和结算记录。

**数据口径与限制**：
- 有发票号不代表发票原件已归档，分别展示数量。
- 历史类型“厂家款”是现有付款分类，不等于厂家真实到账证明，单独提醒。
- 合同、付款与结算采用不同口径；金额差异是人工核对线索，不能据此宣告核销通过。
- 金额采用整数分计算再换算为元。
- 不显示银行账号、不复制账目、不变更归档项目业务状态。

**权限**：服务端 ledger:read 仅总管理员允许；其他所有角色访问列表、明细和导出均返回 403。前端菜单也仅对总管理员显示。

**接口**：
- GET /api/project-ledger
- GET /api/project-ledger/:meetingNo
- GET /api/project-ledger/:meetingNo/export

**验收**：唯一编号跨模块一致、审批后编号不变、六角色权限与未登录访问、精度、发票号与附件区分、非法分页、CSV 数据范围。
